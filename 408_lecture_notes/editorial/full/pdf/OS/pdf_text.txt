第1章
操作系统与程序运行环境
程序执行一条普通加法指令时，通常直接使用处理器；读取文件时，却不能自己任意驱动磁
盘。两种操作的差别来自资源保护：处理器、内存和设备由多个程序共享，操作系统必须管理它
们，并给应用提供受控的使用接口。本章先沿一次程序运行建立用户态、内核态、异常、系统调
用和地址空间之间的关系。
1.1 操作系统管理什么，向程序提供什么
操作系统是控制和管理计算机硬件、软件资源，组织程序运行，并向用户和应用程序提供接
口的系统软件。这里的“管理”要落到具体对象上：处理机管理决定谁运行；内存管理分配空间
并隔离访问；文件管理组织持久数据；设备管理协调输入输出，屏蔽设备差异。
面向用户的命令行、图形界面便于发起操作；面向应用程序的系统调用接口允许程序请求内
核服务。图形界面不是所有操作系统都必须具有的组成部分。编译器虽然也是系统软件，但把高
级语言翻译成目标程序不因此成为操作系统的基本职责。
〖1.1‑003〗下列哪项不是操作系统关心的基本问题：管理裸机、提供用户程序与硬件的接口、
管理系统资源、提供高级语言编译器？答案是最后一项。判断依据是该功能是否承担资源管理与
运行控制，不能只看它是否属于“系统软件”。
并发、共享、虚拟与异步怎样联系
并发指多个活动在同一时间间隔内推进；并行指多个活动在同一时刻执行。一个CPU 交替
执行两个进程，已有并发；多个核上分别执行，才有处理器层面的并行。单CPU 的计算与设备
的数据传输仍可能并行。
共享指资源供多个并发活动共同使用。打印机一类资源通常需要互斥使用；磁盘文件或内存
中只读代码可按规定共享。所谓“同时共享”不等于所有硬件操作都在同一瞬间发生，而是允许
多个活动在同一时期使用同一资源。
虚拟把有限物理资源表现为若干逻辑资源。例如时间片让每个用户似乎独占一个处理器，虚
拟内存让进程使用独立的地址空间。异步指进程因竞争处理器、等待I/O 等原因，以不可预先确
定的速度向前推进。它不表示进程内部可以违背程序依赖，也不等同于接口中的“异步I/O”。
并发活动会竞争资源，因而需要共享与保护；虚拟化为并发活动提供合适的使用视图；资源
等待又造成执行速度的不确定。后续同步与调度问题都以这些关系为前提。

1.2 批处理、分时与实时解决不同的问题
早期人工装入程序时，CPU 常等待操作者准备下一项作业。单道批处理把多个作业预先排
好，自动逐个执行，减少人工干预；但一个作业等待I/O 时，处理器仍可能空闲。多道批处理
允许多项作业同时在内存中，利用CPU 与I/O 的重叠提高吞吐量。中断使设备完成时能够通知
CPU，存储保护、调度和资源管理使多道运行可控。
分时系统把处理器时间分成时间片，轮流服务交互用户，主要关注响应时间和交互性。时间
片不是每个程序的整个运行时间；未完成者会在以后继续执行。实时系统关注任务能否在规定期
限内得到响应或完成。硬实时任务错过截止时间便不能满足系统要求；软实时允许一定程度的超
期，但质量会下降。实时性不能只解释成“运行得快”：提前1 秒与晚于期限1 毫秒的结果，可
能与绝对执行速度无关。

1.3 用户态、内核态与特权指令
处理器的工作模式规定当前代码能够执行哪些受保护操作。用二态模型表示时，用户态权限
较低，内核态权限较高。模式位保存在程序状态信息中，由硬件按规则改变；普通用户程序不能
通过一条普通赋值语句把自己变成内核态。
特权指令只能在规定的高权限模式执行，例如修改关键内存映射、设置中断屏蔽状态、直接
控制受保护I/O。若允许任意用户程序关闭时钟中断，它就可能长期占用CPU，使调度失去控
制。普通算术、逻辑和多数寄存器操作没有这种系统级影响，可以在用户态执行，也可以在内核
态执行。
由此区分“必须在内核态运行”与“只有特权指令才能在内核态运行”。前者约束特权指
令，后者把内核态误解成只能执行特权指令，无法完成内核中的普通计算。陷入指令是用户程序
主动进入受控入口的指令；它允许在用户态执行，执行后由硬件转入规定的内核入口，不能据
“会进入内核”反推它是用户态禁止执行的特权指令。

1.4 中断和异常怎样把控制权交给内核
外部中断由正在执行的指令以外的事件引起，如时钟到期、设备完成。异常由当前指令执行
过程中的事件引起，如除数为零、缺页、执行非法指令；主动执行陷入指令也通过受控异常入口
请求服务。不同教材可能把“中断”作为包括内外事件的总称，本书需要区分时使用“外部中
断”和“异常”。
一次典型控制转移包括以下连续过程：硬件检测事件，保存继续执行所需的断点和程序状
态，按事件号找到处理入口并切换到所需模式；入口代码再保存会被处理程序改写的通用寄存
器，执行处理；退出时恢复相应现场，使用专门返回指令恢复程序状态和继续位置。具体保存位
置和硬件、软件分工取决于体系结构，不能把所有现场都归给同一方。

1.5 系统调用与库函数：调用一段代码，还是请求内核服务
系统调用是应用通过规定接口请求内核服务的过程。程序准备调用号和参数，执行陷入指
令；内核检查参数、权限及资源状态，分派到相应服务；服务完成或进程以后被唤醒继续时，把
结果返回用户程序。检查参数不能省略，例如用户提供的缓冲区地址必须落在允许访问的范围
内。
库函数是程序可以调用的已有函数。纯字符串长度计算可以完全在用户态完成；文件读写库
函数可能整理格式、维护用户缓冲区，再调用read、write 等系统调用。因而“调用库函数”既
不必然发生模式切换，也不排斥发生系统调用。反过来，系统调用也不是普通函数调用：它跨越
保护边界，并通过内核规定的入口执行。
读取磁盘文件时，read(fd, buf, n) 中的fd 标识已经打开的文件，buf 是接收数据的用户
缓冲区，n 是请求字节数。若数据已在内核缓存，内核可能复制后直接返回；若必须等待设备，
当前进程可能先阻塞，CPU 转去运行其他进程。不要把“系统调用进入内核”与“系统调用必
阻塞”合为一条结论。
〖1.1‑010〗库函数不直接处理所有受保护硬件请求。判断一个具体函数是否引起陷入，要看它
在本次路径上是否请求内核服务，不能只凭“库函数”这个名称。
1.6 从源程序到可运行映像：链接、装入与地址绑定

块。
装入把可执行文件需要的内容映射或读入进程地址空间，并建立运行条件。地址绑定可能发

1.7 进程地址空间中，代码、数据、堆和栈各放什么
地址空间是一组可由地址标识的位置。进程的虚拟地址空间提供其运行时看到的地址视图，
不要求这些地址对应的内容全部同时存在物理内存。可执行文件的磁盘布局、进程的虚拟布局、
物理页框布局是三个不同对象。
典型用户空间包含代码区、静态数据区、堆、栈和映射区。代码区存放机器指令，通常只读
且可共享；已初始化的全局变量、静态变量通常在初始化数据区，未显式初始化或零初始化的数
据可用零填充区表示。堆用于动态申请的对象，栈保存函数活动记录中的参数、返回信息与未被
优化掉的自动局部变量。共享库和映射文件可位于映射区。具体地址增长方向和排列由平台决
定，示意图不能代替题设。
考虑以下代码，假定采用常规C 运行时布局且忽略编译优化：
int g = 3;
static int z;
int main(void) {
int n = 16;
char *p = malloc(n);
/* 使用p 指向的空间*/
free(p);
}
g 是初始化静态存储期数据，z 是零初始化静态存储期数据；n 和指针变量p 自身属于main
的局部活动记录；p 指向的动态对象属于堆。指针存在哪里与它指向的对象存在哪里必须分别回
答。不能把“写在函数外”当作“属于代码段”，也不能把所有局部变量都断言为实际驻栈，优
化可能把它们放进寄存器或消除。
进程控制块PCB 保存调度与管理信息，是内核数据结构，不是应用能够随意修改的用户栈
对象。同一程序的两个运行实例可以共享只读代码，但具有不同的进程身份、逻辑状态和数据视
图。
1.8 内核结构：把哪些功能放进同一保护域
分层结构按依赖关系划分功能，上层使用规定的下层服务，便于逐层验证；代价是层次难划
分、调用路径可能增长。模块化结构把功能组织为接口清楚的模块，允许在约定接口下替换实
现。模块划分不自动规定严格的层次调用关系，模块也不等于独立的保护域。
宏内核把较多的管理功能放在内核地址空间中，功能间可以直接调用，通信开销较小；一个
内核模块的错误也可能影响整个系统。微内核把最基本的调度、低级地址空间管理、进程间通信
等保留在内核，把较多服务移到用户态服务器。隔离与替换更容易，但一次服务可能增加消息传
递和保护域切换，不能无条件断言性能更好。
外核进一步把资源保护和复用机制与高层资源抽象分开，让应用或库操作系统按需要实现抽
象。它并非“没有内核”或“不保护资源”；被保留的保护职责恰是其基础。

1.10 虚拟机：客户操作系统也可以成为被管理者
虚拟机管理程序VMM向客户操作系统提供虚拟处理器、内存和设备，安排多个虚拟机使用
物理资源，并隔离其影响。客户操作系统中的“内核态”是客户的权限视图，不意味着它可以越
过VMM 任意修改主机资源。敏感操作由硬件虚拟化支持、陷入模拟或其他受控机制处理，具
体路径随实现变化。
第一类VMM 直接运行在硬件上；第二类VMM 依托宿主操作系统运行。二者都可能采用
硬件加速，不能简单等同于“硬件实现”和“软件实现”。多台虚拟机可以在单核上交替运行，
也可以在多核上并行运行，所以“同时存在多台虚拟机”不能推出它们在每一时刻都真正并行。
进程虚拟地址空间隔离的是进程访存；系统虚拟机为客户操作系统提供完整机器抽象。容器
通常共享宿主内核，通过名称空间、资源控制等隔离进程环境，不等同于每个容器都带一个独立
客户内核。这里用它帮助辨析抽象层次，不要求记忆容器实现细节。

进程、线程、调度与上下文切换
程序是指令和数据的静态描述，进程是程序的一次执行过程及其资源环境。同一可执行文件
运行两次，可以产生两个进程；同一进程又可以包含多个执行线程。判断状态变化时，要分别
问：资源属于谁，当前谁在执行，谁还欠一个事件，谁只是等待处理器。
2.1 进程与线程：资源单位和执行单位
进程是系统进行资源分配和管理的基本单位，具有独立的运行状态和地址空间视图。进程实
体通常由程序段、相关数据和进程控制块PCB 等构成。PCB 记录标识、状态、调度信息、资源
使用信息及保存的处理器现场，内核据此管理进程；“一个进程没有正在占用CPU”不等于它
不存在。
线程是进程内部的一条执行流。在引入线程的系统中，处理器调度通常落实到可调度线程，
而地址空间、打开文件等资源主要归所属进程。每条线程需要自己的程序计数器、寄存器现场、
栈和线程控制信息，否则无法分别记住执行位置和函数调用链。
同一进程的线程可以访问共同的代码、静态数据、堆及进程资源，但拥有独立的执行现场。
说“线程有自己的栈”，是说其函数调用状态分别管理，不能据此认为同进程的其他线程在地址
上绝对访问不到该栈。只要得到有效地址并具备权限，线程仍可能错误地访问另一线程的对象；
私有用途与硬件隔离不同。
进程通常具有动态性、并发性、独立性和异步性。独立性指其运行和管理环境，不表示不能
通信或共享；异步性也不允许违反自身指令的必要依赖。线程有利于把服务器中等待网络、处理
请求等活动组织成多个执行流，但线程数增加同样会带来同步、栈空间和切换开销。
2.2 就绪、运行和阻塞：先判断缺少什么
就绪态表示除处理器外，执行所需条件已满足；运行态表示正在处理器上执行；阻塞态表
示等待I/O、资源、同步事件等条件，暂不能因获得CPU 就继续。单处理器同一时刻至多一个
相应执行实体在运行，就绪与阻塞却都可以有多个。

2.3 用户级、内核级线程与映射模型
用户级线程由用户空间线程库建立和管理，内核可能只看见承载它们的进程或少量内核调度
实体。纯用户级线程切换可以只修改用户现场，开销较小；但在多对一模型中，一个承载实体因
阻塞式系统调用被阻塞，其他用户线程也失去在该实体上执行的机会；内核也无法把这些用户线
程分派到多个核真正并行。
内核级线程由内核识别、管理和调度。某线程阻塞时，同进程的其他内核线程仍可运行；多
个线程也可分派到不同核。代价是创建、管理和切换通常需要内核参与，不能把“用户级线程切
换开销小”列成内核级线程相对用户级线程的优势。

“内核级”描述管理方式，不能理解成该线程的应用代码始终在内核态执行。用户线程进入
系统调用时也可能执行内核代码。线程类型、CPU 当前模式、进程所属地址空间是三个不同判
断维度。
2.4 创建、撤销与组织：PCB 为什么是管理入口
创建进程一般需要分配标识和PCB、建立地址空间和初始数据、关联资源、初始化执行现
场，再加入适当的调度队列。用户登录、启动程序或系统创建服务进程可能触发创建；给已有进
程分配设备只是改变其资源状态，不必产生新进程。
终止进程时，内核停止其执行，处理相关等待与通知，回收资源并释放管理结构。子进程是
否随父进程终止，取决于系统的父子关系政策；不能把级联终止当成所有系统的通则。某些系统
会保留最少退出信息，供父进程取得状态后再完全释放。
PCB 可以用链表、队列或索引表组织。就绪队列按调度规则组织可运行者，事件等待队列
组织等待同类条件者；状态转换时要同步维护状态字段和所在队列。不能只改一个“状态字”而
让进程还留在错误队列中。
线程的创建同样要建立TCB、栈和初始执行现场，但可以复用所属进程的地址空间等资
源。在常规父子进程模型中，父子是两个独立进程，可并发执行、有不同PCB；即使最初采用
写时复制暂时共享物理页，也不是共用一个无区分的虚拟地址空间。真正共享的部分须由共享映
射等机制说明。
2.5 共享内存、消息、管道和信号
共享内存让多个进程把某些虚拟地址映射到共同的物理存储区。建立映射后，数据交换可以
通过普通访存完成，减少反复拷贝；但谁先写、读者何时可读、多个修改者是否冲突，仍需要同
步机制。共享内存不自带“不会竞争”的保证。
消息传递把数据交给消息接口，由发送、接收及相关队列组织通信。直接通信指定对方进
程，间接通信通过信箱或端口；同步发送、异步发送等语义由接口规定。一次接收若没有消息，
可能阻塞，也可能立即报告暂不可用，不能只凭“消息传递”决定状态。
管道提供有次序的数据流通道。经典无名管道常用于有亲缘关系的进程，通常按半双工模型
理解；双向通信可用两个管道。命名管道允许按名称建立联系。管道容量有限，空管道上的阻塞
读、满管道上的阻塞写都会等待；写入数据后，不代表读取者会立即得到CPU。
信号是向进程通知某类事件的机制，如终止请求、定时事件等。信号与信号量不同：前者通
知事件，后者通过许可计数和等待队列协调资源与次序。普通信号也不等同于携带任意大量数据
的可靠消息队列，是否排队等细节须看具体信号类型与接口。

2.7 什么时刻可以调度，抢占改变了哪一步
当前进程结束、主动阻塞或让出处理器，必须考虑选择其他可运行者；新进程到达、I/O 完
成使更合适者就绪、时间片到期，也可能触发重新选择。非抢占方式允许当前运行者继续，直到
结束或主动放弃；抢占方式允许在满足规则的事件点中断当前运行者，把它放回就绪队列。
调度器负责选择，分派器负责把处理器实际交给所选者，包括必要的现场恢复与切换。发生
一次中断不必更换运行者，检查一次调度条件也不等于一定发生进程切换。题目询问“调度次
数”时，应核清是否计首次分派、是否计选择原进程、是否计最后转入空闲；不能把事件点数和
切换次数混算。
内核维护调度结构的短小临界区等不允许任意抢占，否则可能读到队列的半更新状态；处理
中断的阶段也有相应约束。所谓内核可抢占，并非每条内核指令都可以无条件中断并调度。
2.8 沿时间线执行调度算法
处理调度题时，先明确到达时间、服务时间、抢占规则、同刻事件次序及开销。每到一个可
能改变选择的事件点，只在已经到达且就绪的进程中选择，记录剩余CPU 时间。最后用完成时
刻计算指标，并检查CPU 总服务量是否与题表一致。
FCFS、SJF、SRTF 与高响应比
先来先服务FCFS按就绪到达次序选择，通常不抢占。长CPU 段在前时，后面的短进程和

2.9 多处理机调度：负载与缓存都有代价
多个处理器可以使用公共就绪队列，也可以各自维护队列。公共队列便于共享负载，但并发
访问需同步；每核队列降低争用，却可能出现一核排队、一核空闲，需要负载均衡。推迁移由繁
忙者把任务移出，拉迁移由空闲者取得任务。
处理器亲和性倾向让线程继续在此前运行的处理器上执行，利用缓存和地址转换缓存中的内
容。软亲和性是调度倾向，硬亲和性是允许处理器集合的明确限制。负载均衡可能要求迁移，缓
存局部性可能要求保留，二者需要权衡；不能把“每核进程数相同”当作负载完全相同，因为各
任务剩余计算量可能不同。
同时多线程SMT 让一个物理核维护多个硬件线程现场，共享某些执行资源；它不等于每条
逻辑处理器都具有独立完整的执行单元。调度题未给多处理机规则时，不要自行把一个进程拆到
多个核同时加速。
2.10 上下文切换与模式切换
上下文是恢复执行所需的状态，包括程序计数器、寄存器、栈等；进程切换还可能更换地址
空间相关状态。模式切换只是当前执行权限模式改变，例如同一进程进入系统调用再返回；它不
必改变执行身份。上下文切换则把CPU 从一个执行实体交给另一个。
同进程的线程切换通常要换PC、寄存器和栈，而不必更换进程页表基址和共同的文件资
源。跨进程切换还要建立新地址空间环境；TLB 是否必须全部清空，取决于是否支持地址空间
标识等硬件条件。不能把“跨进程切换一定清空全部Cache”列作一般步骤。
〖2.2‑009〗同一进程中T1 切到T2，需要更新各自执行位置和栈环境；进程页表和进程打开文
件资源并不因同进程线程切换而自然改变。判断题列出的每项寄存器，要先说明它保存线程状态
还是进程共享状态。
【2023】“执行系统调用”完成并返回调用者时，可以使CPU 从内核态回到用户态；阻塞、唤
醒和执行CPU 调度本身属于内核管理路径，不能把它们的完成都理解成必然返回用户态。具体
返回到哪个线程，由当时调度与返回路径决定。

资源、代码与先后关系
临界资源是在同一时段只允许一个进程使用的共享资源。临界区是进程中访问相应临界资源
的代码段。进入区负责申请进入，退出区负责释放；二者不属于被保护的临界区本身。资源是一
份共享对象，相关临界区可以有多段，分布在不同进程中。
〖2.3‑027〗5 个并发进程各有一段访问同一变量A 的代码，对应5 个相关临界区。一份共享变
量不能代替五段代码来计数。一般程序若有多处访问，不能仅凭进程数推出代码段总数。
互斥限制重叠：某进程正在访问临界资源时，其他需要访问它的进程须等待。同步规定合作
中的先后关系：后续操作需要某项结果，就必须等产生该结果的操作完成。同一对进程可能同时
受这两种约束。
例3‑1　共享缓冲区中的两种约束

3.8 管程与条件变量：等待时必须让出改变条件的机会
管程把共享数据、对数据的操作过程和初始化封装在一个同步模块中，参与者通过规定入口
访问共享数据；同一时刻至多一个进程在其中执行。这个互斥规则由实现管程的语言或运行系统
保证，不要求调用者在每个入口外重复编写P、V。管程不是一个自行运行的进程。
但“每次只准一人进入”还不够：消费者进入后可能发现无产品。若它在管程里循环等待并
一直保有管程，生产者就无法进入改变条件。条件变量为这种等待提供队列；实际条件由共享数
据上的布尔判断表达，例如count>0。条件变量本身不是保存产品数的整数。
wait 负责等待，不替调用者判断条件
例3‑7　条件变量的wait 做什么
【2018】若x 是管程内的条件变量，则当进程执行x.wait() 时所做的工作是（　）。
A. 实现对变量x 的互斥访问
B. 唤醒一个在x 上阻塞的进程
C. 根据x 的值判断该进程是否进入阻塞态
D. 阻塞该进程，并将之插入x 的阻塞队列中
答案为D。调用者先检查共享状态，只有需要等待时才调用x.wait()；调用后进入x 的等
待队列，并释放管程使用权，让其他进程能进入。C 把“调用前的条件判断”放进了wait 的职
责，还把x 当作可直接判值的资源计数。
管程中执行x.signal()，是通知一个已经在x 上等待的进程。若没有等待者，通知不积累；
以后进入的进程须重新检查共享状态。信号量V 即使没有等待者，也会使计数增加，留下一个
可供后续P 使用的许可。
〖2.3‑029〗“管程中signal 操作的作用和信号量机制中的V 操作相同”不成立。检查无等待
者的边界即可区分：前者不留下通知，后者增加许可。管程作为同步模块，与一个可独立运行的
进程也不是同一类对象；具体语言的管程对象能否实例化，应由语言规定。
通知以后，何时重新检查条件
不同管程定义对signal 后的运行次序有不同规定。Hoare 式语义可立即转交管程给被唤醒
者；Mesa 式语义让通知者继续，等待者以后重新竞争进入权。题目若给出特定语义，应据此推
演，不能混用。

证等它重新取得m 时条件仍成立，所以用while 重检。实际接口还可能出现虚假唤醒，同样需

4.1 死锁、饥饿和不安全状态
死锁指一组进程中，每个进程都在等待只能由组内进程引起的事件（也可能是自身尚未执行
的释放动作），因而这一组无法自行推进。最小的双资源例子是：P 持有A 等B，Q 持有B 等
A；没有进程能到达释放步骤。
饥饿指某个进程长期得不到所需服务，而其他进程仍可能持续前进。例如读者不断加入，使
写者一直拿不到写权限。死循环是执行路径自身不能结束，进程可能仍持续占用CPU，不必等
待其他进程。三者的机制不同，处理方法也不同。

安全状态问的是“能否保证全部完成”
安全序列是进程的一种次序，使每个进程在轮到它时，现有可用资源加上此前已完成进程释
放的资源，足以满足它尚需的最大资源量。存在至少一个安全序列，称当前状态安全。
安全不是说系统实际上只能按这一序列运行；该序列是可完成性的证据。不安全表示无法在
最大需求假设下给出这样的保证，不代表此刻已经死锁。进程可能还没提出全部需求，也可能实
际少用资源或提前释放。死锁状态必不安全；不安全状态可能在以后的某种申请序列中发展成死
锁。
4.2 死锁预防：在规则中破坏一个条件
预防是在分配规则上使至少一个必要条件不能成立，不必等到具体死锁已经出现。
让可共享的资源按共享方式使用，可以去掉相应的互斥条件；但打印机输出、独占锁等具有
不可共享的语义，不能为了避免死锁而取消必要保护。一次性申请运行所需的全部资源，全部满
足才开始，可以破坏占有并等待，但会降低利用率，并要求提前知道需求。申请失败时先释放已
有资源再重试，也是针对保持关系的办法。
对可保存、恢复状态的资源，可以在适当时机剥夺并回滚，例如某些处理器或存储资源；正
在打印到纸张上的半份输出却不能简单撤回。对所有资源规定统一编号，只允许按严格递增次序
申请，可以破坏循环等待：若有环，沿环的资源编号必须不断增大又回到起点，无法成立。所有
进程各自“先拿左边再拿右边”并不保证全局编号递增。
预防可能限制请求方式并造成资源闲置。避免则保留更多请求自由，在每次拟分配时检查结
果能否仍安全。二者都在实际进入死锁前采取措施，但依据不同。

总资源界限不能代替银行家逐态检查
若n 个进程每人最多需要k 个同类不可剥夺资源，为了在任意分配顺序下都保证至少有一个
人能够拿齐，可用最坏状态论证：每人都持有k −1 个仍未完成，共持有n(k −1) 个，再多1 个
即可使至少一人拿齐。所以充分的总量界限是m ≥n(k −1) + 1，即nk < m + n。
这个结论回答的是不加安全检查时的最坏分配保证，不能说成银行家算法能够工作的必要条
件。银行家可以主动推迟不安全请求，使资源较少的系统仍保持安全。例如两进程各最多需要3
个、系统共3 个，完全可以先满足一个，再满足另一个；最大需求之和6 不满足6 < 3 + 2，仍
能安全运行。遇到题干把这两种问题混写时，应先明确要求的是任意分配保证，还是某个状态能
否批准。
4.4 检测、解除和恢复
检测允许系统运行到某种资源等待状态后，再判断是否已经死锁。单实例资源可以构造
进程等待图；多实例资源要结合当前持有量、可用量和当前未满足请求进行化简。这里使用的
Request 是已经提出、正在等待的数量，不是未来最大Need。
令Work 为当前可用量。对当前请求能由Work 满足的进程，假定其继续执行并释放已持
资源，删除其相关分配与请求边，再寻找下一可化简进程。若有持有资源的进程最后仍无法化
简，则该资源等待状态中存在死锁。没有占有任何资源的等待进程可能受死锁影响，却不一定属
于维持资源环的核心；具体“死锁进程集合”的定义与检测初始化规则应一并说明。
例如A、B 各1 个，P 持A 等B，Q 持B 等A，Available 为(0, 0)，两人的当前请求分别
为(0, 1)、(1, 0)。任何人都无法化简。若第三个进程持有另一个B 且能不等待地完成，则它归还
后P 可推进；这就是多实例有环却未必死锁的同一机制。
检测确认死锁后，可以终止全部死锁进程，或逐个选择牺牲者直到环被打破；也可在资源允
许恢复时剥夺资源，并把受影响进程回滚到安全检查点。选择牺牲者需要考虑已完成工作、资源
占用、恢复代价和优先级；每次都牺牲同一个低优先级进程，可能造成饥饿。仅降低某死锁进程

第5章
内存管理：映射、保护与虚拟内存
内存管理同时处理三个问题：程序用什么地址描述对象，这个地址此刻对应哪里，访问是否
被允许。连续分配、分页和分段使用不同的映射单位；请求分页又允许某些合法内容暂不在物理
内存。做题时先区分地址、映射和驻留状态，再进行位数或时间计算。
本章容量中的KB、MB、GB 按题目所采用的二进制单位理解，即210、220、230 B；涉及标
准严格区分时可写KiB、MiB、GiB。地址与页号、页框号从0 编号；十六进制数以H 结尾。
页、页框大小相同；没有特别说明时，地址按字节编址。
5.1 逻辑地址、物理地址和可寻址范围
逻辑地址或虚拟地址是程序在自身地址空间中使用的地址；物理地址标识主存中的实际位
置。CPU 执行访存指令形成虚拟地址，地址变换机构按当前进程的映射得到物理地址，再访问
主存。操作系统创建和维护映射，MMU 等硬件完成通常的运行时查询；缺页或保护异常再进入
内核处理。
若虚拟地址宽v 位、按字节编址，可表示2v B 的虚拟地址范围；物理地址宽p 位，对应的
可寻址物理范围为2p B。实际可用空间还受保留区域、实现的有效位、进程限制及后备存储等约
束。不能用“内存容量加硬盘容量”直接求虚拟地址的位数，也不能从逻辑地址位数自动推出物
理地址位数。
内存按页调入调出，不等于每条CPU 访存都以整页为单位。指令仍可读取一个字节或一个
字，页是映射、分配或传输的管理单位。题目中的地址单位、页大小单位和数据类型长度应分别
记录。
5.2 共享、保护、分配和回收
分配决定哪些物理空间供谁使用，保护限制哪些操作合法，共享则允许多个映射指向同一内
容。基址与界限可以保护连续区域；分页与分段通常在映射项中记录存在、读写、用户/内核等
权限。一个地址有数值，不表示它属于合法映射；一个页面存在内存，也不表示用户可以任意写
入。
共享只读代码时，各进程的页表可以指向同一个物理页框，并禁止写入。共享可写数据则还
需要同步。写时复制先把多个映射指向同一只读物理页，在某个进程需要写时触发受控异常，为
写者分配并复制私有页，再更新映射；它与让所有写者始终修改同一共享页不同。
回收时必须维护使用计数、映射与空闲结构；若另一个进程仍在合法使用共享页，不能因为
本进程退出就立即把页框分给无关对象。页表与TLB 的映射变化也须保持一致，否则旧缓存可
能继续访问已经回收或改变权限的内容。

5.3 连续分配与动态分区：空闲总量不等于可分配块
单一连续分配把内存划分为系统区和一个用户区，不能有效支持多个驻留用户作业。固定分
区预先划定若干区，每区容纳一个作业；作业小于分区时，分区内未用部分形成内部碎片。动态
分区按请求划出连续区域，空闲洞可能被已分配区隔开，形成外部碎片：空闲总量够，仍可能没
有一个足够大的连续洞。
首次适应按地址顺序找第一个足够大的洞；循环首次适应从上次位置继续；最佳适应选择最
小但够用的洞，常需按大小查找；最坏适应选择最大的洞。算法选择的是哪个空闲区，不是把所
有空闲区自动合成一块。最佳适应会留下很小的余量，“最接近请求”不保证长期整体利用率最
好。
释放分区时检查物理地址是否相邻：只与前洞相邻则合并前洞，只与后洞相邻则合并后洞，
前后都邻接则合并三块。按大小相邻的表项未必在物理地址上相邻。紧凑通过搬移已分配内容把
分散空洞合成大洞，需要可重定位支持和搬移成本，也不能与普通释放合并混同。

5.5 TLB 与多级页表：空间与时间分别计算
多级页表为什么可以节省空间
若虚拟页很多，单级页表需要大量表项，即使大部分虚拟区间根本没有使用。多级页表先用
高层目录找到所需下级页表，仅为实际使用区域建立相应下级表；各下级表可分别放置，不需一
块容纳整张大页表的连续内存。
多级页表不能减少“一个最终映射项本身需要的位数”，也不保证为一个占满全部虚拟空间
的进程节省总空间；全展开时还增加目录开销。它的收益主要在稀疏空间和分级分配，代价是未
命中转换缓存时要多次查表。

5.7 请求分页：合法但不驻留时会发生什么
局部性是程序在一段时期内倾向反复访问某些对象或其相邻位置。时间局部性来自循环与重
用，空间局部性来自顺序指令、数组邻近元素等。虚拟内存利用这种特征，只保留当前所需部
分，并在需要时调入其他部分，不要求整个进程同时装入。
请求分页的页表项需要区分页面是否驻留，并记录调页所需位置与状态。存在位表示是否
在内存；访问位帮助估计近期使用；修改位表示装入后是否被写过，关系到淘汰时是否必须回
写。修改位不是写权限位：允许写但尚未写的页可以是可写且M=0；只读保护检查则发生在实
际写入前。
一次访存的分支应顺着执行：检查地址合法性，查询TLB/页表并检查存在状态与访问权
限；合法但不驻留则引发缺页异常，内核定位后备内容，取得空闲页框或选择牺牲页；牺牲页若
为脏页且需要保留则回写，调入所需页，更新页表和TLB，重新执行被中断的访存。访问非法
地址应按错误处理，不能一概“给它调一页”。

5.8 页框分配与置换范围
驻留集是进程当前在内存的页面集合。固定分配给进程固定数量页框；可变分配允许按运行
状况调整。局部置换只在本进程驻留集中选牺牲页；全局置换可从其他进程等更大集合中选择，
会改变各进程实际占有的页框量。
因此经典组合中，固定分配通常配局部置换；可变分配可以局部或全局置换。把固定分配与
一般全局置换直接组合，会使被换出进程的页框量改变，违背这里“固定”的约定。分配可按平
均、进程大小或优先级等方法进行，但还须满足体系结构要求的最少页框数。
请求调页在真正缺页时装入，能减少无用装入；预调页根据局部性提前带入可能需要的内
容，可以减少后续等待，也可能调入没用的页。回写策略、清洁页缓冲和空闲页队列影响缺页处
理代价，不能只盯着替换算法名称。
5.9 页面置换：必须跟踪实际状态
OPT淘汰未来最长时间不再访问的页，未来不再访问者优先；它需要未来信息，主要用作
比较基准。FIFO淘汰最早装入者，命中通常不改变装入顺序。LRU淘汰最近最久未使用者，每
次命中也要更新最近使用关系。只在缺页时更新LRU 次序，会把它错误地执行成接近FIFO。

5.10 内存映射文件：把文件内容放入虚拟地址视图
内存映射文件把文件的某个范围与进程一段虚拟地址范围关联，程序通过访存访问映射内
容，系统用分页等机制按需建立驻留页。它省去了应用反复显式调用读写并维护用户副本的某些
工作，但不表示文件整体一次性进入物理内存，也不表示每次访存立即写到磁盘。
共享映射可让多个进程看到同一文件内容，因而支持进程间通信；对共享可写页的竞争仍须
同步。私有映射的修改可通过写时复制保留为本进程私有，不必改原文件。页到文件块的后备关
系由映射与文件系统共同维护，不能把它理解成绕过文件系统而直接把磁盘地址当内存地址。
映射以后仍受地址范围和权限约束，映射建立、页面驻留、写回持久化是不同事件。题目若
问磁盘I/O 次数，要检查页面是否已缓存、是否发生缺页、脏页是否回写，不能仅按源代码中的
读写次数计算。
5.11 工作集、抖动与平均访问时间
工作集是在给定窗口内实际访问过的不同页面的集合。若窗口按最近∆次引用定义，就从
当前位置向前数∆次引用，再去重；不能先数∆个不同页。驻留集描述当前物理状态，工作集
描述近期访问需求，工作集不必总是驻留集的子集：刚需要但尚未调入的页就可能属于需求而不
驻留。

文件、目录与文件系统
文件系统把“按名称找到数据”分成几步：由路径查目录项，由目录项找到文件控制信息，
再把文件内偏移转换成存储块位置。目录、索引节点、打开文件表和数据块分别承担不同工作，
不能把它们都叫作“文件的信息”而混算访问次数。
本章文件内字节偏移和逻辑块号从0 开始；“第几个记录”若采用自然序号则从1 开始。除
题目另有定义，1 KB 为1024 B。计算访盘次数时，逐次说明哪个目录块、索引块或数据块尚不
在内存；已缓存的内容不重复计入。
6.1 文件、文件控制块与索引节点
文件是具有名称和一定属性的持久数据集合。从使用者看，它可以是字节流，也可以由记录
组成；从存储看，它最终占据若干物理块。文件的名称与内容不是同一个对象，一个文件可以通
过多个名称被访问。
文件控制块FCB是系统描述和管理文件的数据结构，通常记录类型、大小、所有者、权
限、时间和存储位置等元数据。将文件名与其他描述信息分离时，目录项可只保留“文件名—索
引节点号”，其余信息由索引节点inode保存。inode 是这种设计中的文件控制信息载体，不
是文件数据块，也不只是“指向文件的一个指针”。
索引节点号的意义局限于相应文件系统，不能只凭两个分区上的编号相同就判断是同一个文
件。内存中的inode 还可包含运行时锁、引用计数等；它与磁盘中持久保存的inode 相关，但
字段不必完全相同。
目录本身也是文件，其中存放的是用于查找对象的目录项；普通文件的数据内容不因为名字
出现在目录中，就都存入目录。采用inode 的模型还应区分三个位置：名字在目录项中，属性
和块地址在inode 中，用户内容在数据块中。
6.2 建立、打开、读写、关闭与删除
建立文件要分配文件控制信息，在父目录增加名字与文件标识的关联，并按规则初始化属
性；空文件可以暂不分配实际数据块。打开文件按路径查找、检查权限，在内存建立或引用打开
状态，返回文件描述符。打开不等于把整个文件内容读入内存。
一个常用抽象分为三层：进程文件描述符表把小整数fd 指向打开实例；打开实例保存本
次打开的状态，例如当前文件位置和访问方式；内存inode 保存文件本身的共享属性及定位信
息。不同教材有时把后两层合称系统打开文件表，本书计算前会按字段所属说明，避免因表名不
同把状态混在一起。
read(fd,buf,n) 根据打开状态和当前偏移找到目标数据，必要时发起I/O，向用户区返回实
际读到的字节，并更新相应文件位置。write 可能分配新块、改变大小、把缓存标记为脏；返回
成功不必表示数据已立即持久化到盘片。文件结束、短读、权限错误等应按题给语义处理。

保护回答谁能对对象执行什么操作。口令、加密和访问控制各有作用，不能相互替代：加密

调度优先级。
访问矩阵以主体为行、对象为列，格中保存允许操作集合。按对象列存放形成访问控制表

查。

6.4 逻辑结构：字节流和记录怎样被使用
无结构文件向应用提供字节序列，记录边界由应用自行解释；所谓无结构不是没有字节顺
序。有结构文件由记录组成，可以定长或变长。定长记录且不跨块时，记录位置容易由长度计
算；变长记录需要额外的边界、长度或索引信息。
顺序文件按记录次序存放，适合顺序处理；按关键字组织的顺序文件可利用有序性查找，但
插入维护可能较贵。索引文件为记录或记录组维护索引，便于定位；索引顺序文件把顺序组织与
索引结合。这些是应用看到或逻辑层规定的记录组织，和下面“一个文件的物理块连续、链接还
是索引分配”不是同一维度。
例如变长记录文件可以用一个逻辑索引定位记录所在字节范围，文件本身再通过物理索引块
定位磁盘块。两个“索引”服务不同层次，题目问哪个对象的空间、哪个访问链，就沿对应关系
计算。
6.5 物理分配：连续、链接与索引
连续分配记录起始块与长度，逻辑块k 直接映射为起始块加k，顺序和随机访问都容易；但
文件增长可能受相邻空间限制，空闲空间也可能有外部碎片。按区段扩展可缓解增长问题，但不
是每个文件永远只有一个连续区间。
隐式链接分配在各数据块内保存后继块号，目录记录首块等信息。逻辑上连续的数据可散在
任意物理块；增长容易、无需一个大连续洞，但要找后面的块通常必须沿链读取，链指针也占用
空间。损坏一个指针会影响后续定位。
显式链接分配把后继关系集中到文件分配表FAT。表若驻留内存，沿链查找不必每步读取数
据块，但定位第k 个簇仍要执行链追踪，不等于具有直接随机下标。FAT 一般为每个受管簇保
存一项，规模取决于受管卷的簇数；不能单凭某个文件最大长度就一般性推出整个卷的FAT 大
小，除非题目另外限定两者关系。
索引分配为文件记录各逻辑块的物理块号，可单级、多级或混合索引。根据逻辑块号查相应
索引项即可定位，支持随机访问；索引本身占空间，小文件使用大索引块时可能浪费。UNIX 式
混合索引让小文件直接索引，大文件逐渐使用间接层级。

6.6 目录和路径解析：逐层找到名字
单级目录把所有文件名放在一张表，简单但命名冲突多；两级目录按用户分开，缓解重名但
共享和多层分类受限；树形目录让目录内再有子目录，便于按层次组织。绝对路径从根开始，相
对路径从当前工作目录开始；. 表示当前目录，.. 表示父目录，在权限与挂载规则允许的范围
内解析。
访问/home/u/a.txt 不能在一张全局名字表中凭空跳到数据。典型inode 模型先从根目
录查home，取得其inode，再查u，最后在该目录中查a.txt 并取得文件inode。各层目录、
inode、数据是否缓存，决定实际I/O 数；路径分量的数量本身不是总访盘次数。
采用“名字与inode 分离”可以使目录项更小，一块容纳更多名字，从而减少线性查找的
目录块数。以王道书§4.2 的目录模型为例，3200 项、每项16 B、每块1024 B，需要50 个目
录块。若目标等概率落在任意一项，且逐块线性查找，各块恰有相同数量目录项，则平均读取
(1 + 50)/2 = 25.5 个目录块；随后再读1 个inode 块，总期望26.5 次。用50/2 + 1 = 26 是“大
量目录块”的近似，不能当作相同概率模型下的精确值。
若目录使用哈希或树索引，查找次数应按相应结构计算；若预先只读入目录的一部分，也不
能把剩余查找都视为零成本。当前工作目录使常用路径可以省去重复解析共同前缀，但不取消权
限检查。
6.7 硬链接、软链接与什么时候回收文件
硬链接是另一个目录项直接指向同一文件inode；多个名字地位相同，不存在“原名字一
删，另一个就失效”的必然关系。增加一个硬链接通常增加inode 的硬链接计数，删除一个名
字减少计数；计数归零且不再有有效使用引用等条件满足后，才能回收数据和inode。硬链接通
常不能跨文件系统，因为inode 编号必须在本文件系统解释；通常也限制用户为目录建立硬链
接，以避免目录环等管理问题。
软链接或符号链接是一个特殊文件，内容保存目标路径。访问它时再解析该路径；目标被删
或移走后，软链接本身仍可存在，只是成为悬空链接。它可以跨文件系统，也可指向目录；相对
目标路径的解释与链接所在位置有关，不能一概按调用者当前工作目录处理。

6.8 文件系统的磁盘结构与内存结构
磁盘上的引导控制信息用于启动；卷控制块或超级块记录块大小、卷规模、空闲管理等总体
信息；目录和inode 区描述对象与名字；数据区保存内容。具体文件系统可采用其他布局，题
目若给不同结构，应以其字段为准。不能把每个文件的所有索引都放入超级块。
挂载后，内存中维护已挂载文件系统信息、目录缓存、inode 缓存、系统打开对象以及进程
描述符表等。缓存加快访问，却要求修改与持久化有规则。一次文件扩展可能同时修改数据块、
空闲位图、inode 大小和块地址；若只写了一部分就断电，会出现泄漏或结构不一致。
一致性检查可以扫描目录、inode 与块使用关系，找出不一致；日志机制先记录需要完成的
更新，再按规则提交和重放，减少崩溃后恢复工作。日志不表示任意用户数据都自动获得完整事
务语义，其保证取决于记录元数据还是数据、提交和写回的具体规则。此处用于解释多结构更新
的因果，不扩展为某种文件系统的实现手册。
6.9 空闲空间：位图、空闲链和成组链接
空闲表记录连续空闲区的起点与长度，适合按区段管理；空闲链把空闲块或空闲区串起
来；位图为每个受管块保留一位，值表示空闲或占用，具体0、1 意义由题目规定；成组链接把
若干空闲块号存成一组，用组内的连接信息指向后续组，并在内存保留当前组的块号栈。
位图大小主要由受管总块数决定，不随当前空闲块数改变；空闲表、空闲链所需内容则与当
前空闲分布相关。成组链接是用少量组连接组织大量空闲块号，不是把所有文件的数据链混在一
起。

I/O 管理、设备软件与外存调度
应用说“读一个文件块”，设备却接收具体的命令、地址和长度。操作系统在中间完成命
名、保护、排队、缓冲和状态通知。本章沿一个请求追踪软件与硬件的分工，再把缓冲时间和磁
盘运动转成可计算的过程。
7.1 设备、控制器、接口与端口
设备完成实际输入、输出或存储，设备控制器管理设备动作并向主机提供寄存器等接口。控
制寄存器接收命令与参数，状态寄存器反映就绪、忙、错误等状态，数据寄存器或缓冲区承载数
据。端口在此通常指可访问的接口寄存器位置，不是网络中传输层端口号。
独立编址的I/O 端口由专门I/O 指令访问；内存映射I/O 把接口寄存器放入地址空间，通过
相应访存指令访问，但访问副作用和缓存属性必须按设备规则处理。接口地址是控制器寄存器的
地址，不是设备所保存文件的字节偏移。
字符设备通常按字符流组织，不适合按任意字节地址定位，例如终端；块设备按可寻址数据
块组织，可进行块号访问，例如磁盘。网络设备按分组收发，还涉及通信地址和协议，不宜机械
套成磁盘的寻道块模型。
独占设备在一次使用期间交给一个使用者；共享设备允许多个作业在一段时期内交替提交请
求。共享不要求多个物理操作在同一瞬间执行。设备是否可寻址、是否共享、是否可随机访问是
不同分类维度，不能把字符设备定义成“可按字节地址随机访问”。
7.2 轮询、中断和DMA：谁搬数据，谁等待
程序查询或轮询由CPU 反复读状态，设备就绪时再执行数据传送。实现简单，但忙等期间
CPU 不能有效做别的工作。中断方式启动设备后允许CPU 执行其他任务，设备在需要服务或完
成时发中断，CPU 进入中断服务程序处理；若每次数据通过CPU 的读写指令搬运，数据通路仍
经过CPU。
DMA由专门硬件按驱动设置的地址、长度和方向，在设备与内存之间传送数据。CPU 负责
启动、异常和结束处理，不必逐字执行搬运指令；DMA 需要获得总线或内存访问机会，仍可能
与CPU 竞争存储带宽。DMA 结束通常通过中断通知，所以“DMA 与中断不能共存”不成立。

7.4 阻塞、非阻塞与异步接口
阻塞I/O在操作暂不能完成时，使调用线程等待；非阻塞I/O在暂不能立即完成时返回相应
状态，让程序决定重试、处理其他事务或等待通知。反复调用非阻塞接口也可能形成忙等，接口
不阻塞不表示自动提高利用率。
异步I/O把提交与完成分开，提交后程序继续执行，以后通过通知、完成队列等取得结果。
非阻塞主要回答“本次调用等待不等待”，异步主要回答“操作完成如何与调用者联系”，不能
把二者作为完全相同的术语。具体接口是否可能立即完成、如何报告部分完成，要按题设。
字符设备常有字符流、行缓冲等语义，块设备有块号和对齐约束，网络接口涉及发送、接收
和连接/分组。设备无关性是给上层适当统一的抽象，不是强求所有设备具有完全一样的操作集
合。
7.5 缓冲：把输入、复制与计算放到同一时间线
缓冲在生产者和使用者之间暂存数据，可以缓和速度差、适配传送单位、允许阶段重叠。高
速磁盘缓存还可利用重复访问、预读和延迟写，减少某些实际I/O。缓冲区不改变设备本身的物
理速度，也不会无条件消除所有等待。
设每块从设备输入系统缓冲耗时T，从系统缓冲复制到用户工作区耗时M，CPU 分析该块
耗时C。假定输入可与CPU 工作重叠，复制与分析共用相应CPU 资源不能互相重叠，只有一
个用户工作区，并忽略其他开销。
单缓冲中，设备不能在缓冲尚未复制完时覆盖它；复制下一块也不能覆盖仍在分析的用户工
作区。因此第一块先经T + M，以后相邻复制完成点之间是max(T, C) + M，最后还要完成最
后一块的分析。对n ≥1 块：
Tsingle = T + M + (n −1)[max(T, C) + M] + C.
双缓冲允许设备填另一个系统缓冲，而CPU 使用前一个。流水阶段可看成设备输入T 与
CPU 的复制加分析M + C，在上述资源模型下：
Tdouble = T + (n −1) max(T, M + C) + M + C.
这些是从阶段占用关系推出的公式。题目改成两个用户工作区、复制不用CPU、半双工链
路或其他限制时，先重画时间线，不能只凭“单缓冲/双缓冲”名称直接套式。

7.6 设备分配、逻辑名称与驱动接口
设备分配要检查设备类型、访问权限、当前占用、逻辑名称到实际设备的映射，并选择可用
设备与相关控制器、通道等资源。若需要的资源暂不可得，要按规则排队，不能只分配设备却忽
略它必须使用的传输路径。资源逐项申请还可能与第4章的死锁条件相遇。
静态分配在作业开始前取得所需设备，减少运行中占有并等待，但利用率可能低；动态分配
在使用时申请，更灵活，也需处理等待和安全。独占与共享是设备使用性质，静态与动态是分配
时机，不能完全一一对应。

7.7 SPOOLing：先进入磁盘井，再使用独占设备
SPOOLing利用磁盘上的输入井、输出井和相应进程，把低速独占设备的使用与应用运行
分开，形成假脱机工作方式。输入进程把设备数据预先送入输入井，作业随后从井取数据；输出
请求先进入输出井，由输出进程按队列统一送到真实设备，井管理负责记录请求与存储位置等。
打印时，多个进程可以分别提交打印文件和请求，提交后继续做别的工作；打印守护进程再
逐份占用物理打印机。用户看到逻辑上可共享的打印服务，打印机仍一次打印一个任务。不能把
“将独占设备改造成共享设备”理解成硬件突然能同时输出多份互不干扰的纸张。
井通常在磁盘，不是简单把所有输出永久留在内存；SPOOLing 也不是用一台专用外围机
完全脱离主机运行。多道程序设计让井管理、设备服务与用户作业可以并发，缓冲协调暂存数
据，二者分别承担不同作用。
7.8 磁盘结构、地址与格式化
磁盘盘面有磁道，同半径磁道形成柱面，磁道再分扇区。移动磁头到目标磁道需要寻道时
间，等待目标扇区转到磁头下需要旋转延迟，实际数据经过磁头需要传输时间。常规平均模型为
Taccess = Tseek + Trotation + Ttransfer.
若转速为r 转/秒，一圈为1/r 秒，随机角位置下平均旋转延迟为1/(2r)。若题目直接给r
秒/转，则平均延迟为r/2，两种r 单位不能混用。一个磁道能传N B，连续读取b B、忽略跨道
与间隙时，传输时间近似为(b/N)/r 秒。
例如7200 转/分为120 转/秒，一圈约8.333 ms，平均旋转延迟约4.167 ms。若平均寻道
5 ms、目标连续数据传输0.5 ms，则平均访问约9.667 ms。这是原创单位示例，用于把rpm
换成时间；跨道访问若需额外寻道，不能继续当作同一连续磁道传输。

7.9 磁盘调度：把运动顺序和运动距离分开
FCFS按请求到达次序服务，公平直观，但相邻请求可能使磁头来回移动。SSTF每次选离
当前磁头最近的请求，可减少当前一步的寻道，但不是求整个序列的全局最短路径；远处请求可
能长期被新来的近处请求越过。
SCAN沿一个方向服务，达到规定端点后反向；LOOK到该方向最后一个请求便反向，不
必到物理端点。C‑SCAN只在一个方向服务，到端点后回到另一端，返回过程中不服务；C‑
LOOK在本方向最后请求处回跳到另一侧第一个请求。回跳会不会计入移动距离、是否规定到物
理端点、何时停止统计，要按题干，不能只看算法名。

7.10 SSD：没有寻道，不等于没有管理开销
SSD 采用闪存，访问不需要机械寻道与旋转。闪存通常按页读取或编程，按更大的擦除块擦
除；已写内容一般不能像内存字节那样任意原地覆盖，修改常通过异地写入并更新映射实现。闪
存转换层FTL维护逻辑地址到实际闪存位置的映射，与文件系统的文件偏移映射不是同一层。
异地更新使旧页失效，垃圾回收选择块，把仍有效内容迁走，再擦除整块以供后续使用。这
会增加内部写入量，形成写放大；备用空间和回收策略会影响性能，不能只用接口带宽计算每次
小写的真实代价。
擦写次数有限，磨损均衡避免少量块被反复使用。动态磨损均衡主要在新写入时平衡可选空
闲块；静态磨损均衡还迁移长期不变的冷数据，让长期占用低磨损块的空间也参与使用。目的是
均衡磨损、延长寿命，不保证每次请求更快。
TRIM 等通知让设备知道哪些逻辑数据已不再需要，有助于回收；文件删除、文件系统取消
映射和设备实际擦除也不是同一瞬间。由于没有机械位置，传统寻道调度的优势不再原样成立，
但请求合并、公平性、队列深度与写入管理仍有意义。
