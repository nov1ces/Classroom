# 指令系统与 C 程序的机器级表示 {#co-ch4}

## 指令字段怎样决定可表示的操作和地址 {#co-04-01}

一条机器指令包含操作码以及完成该操作所需的其他字段。操作码规定做什么，地址字段可能给出立即数、寄存器编号、形式地址、位移或寻址方式，不能把所有字段都当成主存绝对地址。指令字长是指令编码的位数，机器字长是整数运算的基本位宽，两者不必相等。

按显式操作数地址字段数，可以有零地址、一地址、二地址、三地址指令。零地址指令未必不操作数据，栈式机器的加法可隐含从栈顶取两个数；一地址指令可隐含累加器；二地址形式常让一个地址同时承担源和目的，但具体语义仍要由题目给出。不能只根据“两个字段”推出固定访存次数，字段还可能指定寄存器或立即数。

数据传送指令移动或复制值；算术逻辑指令形成新值和可能的标志；转移指令改变后继执行地址；调用在转移前保留返回位置，返回根据保存的位置继续；输入输出及系统控制指令还可能有权限限制。通常的赋值和算术指令不会把源操作数“取走后清空”。

固定长度操作码用 k 位可区分至多 $2^k$ 种编码。扩展操作码把部分短编码保留为扩展前缀，用更长的操作码表示操作数较少的指令。已作为短指令使用的编码不能同时作为长指令前缀，否则译码会歧义。

### 例 4-1 【2022】　扩展操作码应逐层扣除哪些前缀 {#co-ex4-1}

设计某指令系统时，假设采用16位定长指令字格式，操作码使用扩展编码方式，地址码为6位，包含零地址、一地址和二地址3种格式的指令。若二地址指令有12条，一地址指令有254条，则零地址指令的条数最多为（　）。

A. 0　 B. 2　 C. 64　 D. 128

**解析。** 二地址格式需要12位地址，短操作码为4位，共16种前缀，用掉12种，剩4种可扩展。每个前缀再接6位，共提供 $4\times64=256$ 种一地址操作码；用掉254种，剩2种再各扩展6位，得到 $2\times64=128$ 条零地址指令，选 **D**。

不能从 $2^{16}$ 中只减“12+254”，因为每条二地址指令还对应 $2^{12}$ 种操作数字段组合，每条一地址指令对应 $2^6$ 种组合。逐层保留前缀的算法直接反映译码过程，也方便处理其他字段长度。

## 从形式地址到有效地址 {#co-04-02}

以下记指令地址字段为 A，寄存器 R 的内容为 (R)，内存地址 x 的内容为 M[x]，有效地址 EA 是最终操作数所在的主存地址。立即数不需要另求操作数主存地址；寄存器寻址的操作数也在寄存器，不应为凑公式虚构一次主存访问。

| 寻址方式 | 操作数或有效地址 | 核对条件 |
|---|---|---|
| 立即 | 操作数在指令中 | 字段的符号扩展规则 |
| 直接 | EA=A，操作数=M[A] | A的编码范围 |
| 一次间接 | EA=M[A] | 先取地址，再取操作数 |
| 寄存器直接 | 操作数=(R) | 字段是寄存器编号 |
| 寄存器间接 | EA=(R) | 寄存器保存的是地址 |
| 基址 | EA=(BR)+位移 | 位移位宽及符号 |
| 变址 | EA=A+(IX) | 元素下标是否已乘元素宽度 |
| 相对 | 目标=PC基准+位移 | PC指当前还是后继地址 |

间接寻址得到的中间地址位宽可能大于指令地址字段，从而扩大可寻址范围，代价是增加寻址访存。基址可用于程序重定位，变址适合数组遍历；二者都可表现为寄存器加位移，但所赋予寄存器的用途不同，具体机器也可能用同一种编码机制实现。

### 例 4-2 【2009】　相对转移用哪个 PC {#co-ex4-2}

某机器字长为16位，主存按字节编址，转移指令采用相对寻址，由两个字节组成，第一个字节为操作码字段，第二个字节为相对位移量字段。假定取指令时，每取一个字节 PC 自动加1。若某转移指令所在主存地址为2000H，相对位移量字段的内容为06H，则该转移指令成功转移后的目标地址是（　）。

A. 2006H　 B. 2007H　 C. 2008H　 D. 2009H

**解析。** 指令从2000H开始，占2 B，取完后 PC=2002H。相对位移为+6，目标为2008H，选 **C**。若位移字段改为 FAH且按8位补码解释，则位移为−6，目标为1FFCH；不能把 FAH当作正250。PC基准必须根据本题更新时机确定。

数组寻址还需区分元素下标和字节偏移。按字节编址、int为4 B时，`a[i]` 地址为base+4i。某 ISA 若有“比例变址”，可由硬件将索引乘4；没有时由移位或其他指令形成4i。这不意味着数组元素之间多留了3个空洞，四个字节共同存一个元素。

### 访存次数要从执行路径数

若指令为一个字、无Cache、无预取，直接寻址的读操作数指令通常至少取指一次、取操作数一次；一次主存间接寻址再多读一次地址。若还写回主存，需另计一次写。若指令跨两个存储字、发生缺页或含两个主存操作数，次数会改变。“寄存器间接”中的“间接”不会额外读一次主存地址，因为地址已经在寄存器中。

## 大端、小端和对齐解决不同问题 {#co-04-03}

多字节数据的大端方式把最高有效字节放在最低地址，小端方式把最低有效字节放在最低地址。它只改变一个多字节对象内部的字节排列，不反转每个字节的位，也不改变数组元素顺序。

32位值 `12345678H` 从低地址到高地址，大端为12、34、56、78，小端为78、56、34、12。讨论“高位字节”指数字意义上的高位，讨论“高地址”指位置，两个维度应明确分开。

对齐是对象起始地址满足指定倍数。常用自然对齐模型中，2 B对象起于2的倍数，4 B对象起于4的倍数。结构体编译器可能在成员间和末尾加入填充，使成员地址和相邻数组元素都满足对齐规则。具体要求属于 ABI/编译器约定，题目已给“按边界对齐”时再按给定类型大小执行。

### 例 4-3 【2012】　先确定结构布局，再看低字节 {#co-ex4-3}

某计算机存储器按字节编址，采用小端方式存放数据。假定编译器规定 int 型和 short 型长度分别为32位和16位，并且数据按边界对齐存储。某 C 语言程序段如下：

```c
struct {
    int a;
    char b;
    short c;
} record;
record.a = 273;
```

若 record 变量的首地址为0xC008，则地址0xC008中的内容及 record.c 的地址分别为（　）。

A. 0x00，0xC00D　 B. 0x00，0xC00E  
C. 0x11，0xC00D　 D. 0x11，0xC00E

**解析。** a占偏移0至3，b占偏移4。下一地址偏移5不是2的倍数，须填充1 B，c占偏移6、7，故c地址为C00EH。$273=\mathtt{00000111H}$，小端最低地址保存低字节11H，选 **D**。填充来自对齐，低字节11来自字节序，两步不能互相代替。

![结构体成员、填充与低地址字节分别标明](CO_F05_struct_layout.png){#co-fig-struct width=95%}

二维数组按行优先存放时，`a[i][j]` 的元素偏移为 $i\times\text{列数}+j$，字节偏移还要乘元素字节数。对补码负的 short，先求完整16位编码，再按字节序拆开。例如−6为 `FFFAH`，小端低地址是FA、下一字节是FF，不是把真值“−6”拆成十进制字符。

## RISC 与 CISC：设计倾向不代替具体实现 {#co-04-04}

RISC通常采用较规整的指令格式、较少的寻址方式和Load/Store风格：算术逻辑操作主要在寄存器间进行，访存由装入和存储指令承担。这有利于规整译码和流水处理。CISC往往支持更丰富的指令形式与寻址方式，单条指令可以表达较复杂操作。

“RISC”不等于所有指令永远一个周期完成；Cache缺失和乘除等都可能增加时间。CISC也能采用流水线和内部微操作等技术。硬布线和微程序是实现控制器的方式，不能仅由缩写绝对断言某台具体处理器的全部内部实现。

### 例 4-4 【2025】　RISC 设计能否支持流水线 {#co-ex4-4}

下列关于 RISC 的叙述中，错误的是（　）。

A. 多采用硬连线方式实现控制器  
B. 通常采用 Load/Store 型指令设计风格  
C. 难以采用流水线数据通路实现微架构  
D. 多采用寄存器传递过程调用时的参数

**解析。** 格式规整、操作较简单，通常有利于流水线实现，所以 C 错。A、B、D描述常见设计倾向，不应将“多采用”改读成“只能采用”。答案为 **C**。

## 编译、汇编、链接怎样确定程序中的地址 {#co-04-05}

第1章已给出工具链顺序，这里进一步说明为什么目标文件未必能直接运行。编译和汇编时，一个模块可能引用另一个模块的函数或全局变量，汇编器尚不知道它的最终地址，只能留下符号与重定位信息。链接器合并相应节，解析符号，再按选定地址修改相关引用。

可执行文件包含机器代码，也含装入所需的组织信息；并非文件的每一个字节都被 CPU 当作指令。目标文件还可能含符号表、调试信息和重定位记录。高级语言的变量名在运行时未必仍对应一个固定主存地址，优化后它可能在寄存器中、被折叠成常量，或已经消失。

### 例 4-5 【2022】　工具链顺序 {#co-ex4-5}

将高级语言源程序转换为可执行目标文件的主要过程是（　）。

A. 预处理→编译→汇编→链接  
B. 预处理→汇编→编译→链接  
C. 预处理→编译→链接→汇编  
D. 预处理→汇编→链接→编译

**解析。** 先处理源文件中的预处理指令，再将高级语言翻译成汇编表示，继而编码为目标文件，最后解析跨模块引用，选 **A**。这是题目采用的典型静态编译流程；动态链接将部分工作留到装入或运行时，不改变汇编编码必须在普通机器执行之前完成这一点。

## 分支和循环怎样改变 PC {#co-04-06}

机器执行选择结构时，先形成条件，再决定是否改变后继地址。条件可由比较指令设置标志，也可由分支指令直接比较寄存器。翻译 C 条件时，必须保留 signed/unsigned 的区别，不能因为两者都使用减法硬件就使用同一个转移条件。

下列教学指令约定整数均为32位、R1存x、R2存y，`bge` 按有符号数比较，标签代表指令地址；假定本例的差值可用32位有符号数表示：

```text
    bge R1, R2, ELSE     // x>=y 时跳过 then
    sub R3, R2, R1      // then: z=y-x
    jump END
ELSE:
    sub R3, R1, R2      // else: z=x-y
END:
```

这里为实现 `if(x<y) z=y-x; else z=x-y;`，分支条件采用原条件的否定，使满足原条件时顺序落入 then。转移目标是代码位置，不是把标签的字符存进 PC。

循环先确定入口测试、循环体、更新和回边。对以下机器级教学轨迹，R0为数组基址，R1为元素下标，R2为和，R3为元素个数，int占4 B：

```text
    R1 <- 0; R2 <- 0
TEST:
    if R1 >= R3 jump EXIT
    R4 <- R1 << 2
    R5 <- M[R0 + R4]
    R2 <- R2 + R5
    R1 <- R1 + 1
    jump TEST
EXIT:
```

R3=0时直接退出，不读 `a[0]`；R3=3时读取偏移0、4、8而非0、1、2。这两个边界足以检查循环上下界和地址单位。若变换为指针遍历，每轮指针加4，终止地址为base+4R3；不能把终止地址当成最后一个有效元素地址。

逆向读代码时，先标各寄存器初值和更新式，再识别分支条件。循环回边指令的执行次数与循环体次数可能不同：入口先测的 n 次循环，测试通常执行 n+1次。算动态指令数和 Cache 访问次数时，这个差别不能省。

## 过程调用为什么要保存返回位置 {#co-04-07}

调用至少要解决四件事：把参数交给被调过程，记录返回位置，给局部变量和临时值安排空间，将返回值交回调用者。ISA提供调用、返回或寄存器转移等基础机制，ABI进一步规定参数寄存器、返回值位置、栈对齐，以及哪些寄存器由哪一方保存。

返回地址可以放到栈，也可以先放到链接寄存器。若采用链接寄存器，叶子函数可能不访存保存返回地址；会再次调用其他函数的过程通常需要在覆盖链接寄存器前保存它。不能把“返回地址一定写主存”当成所有指令系统的共同特征。

以下采用一个明确的栈模型说明调用：栈向低地址增长，每槽4 B，SP指向当前栈顶；push先SP减4再写，pop先读再SP加4；调用压入后继指令地址，返回弹出该地址送PC。调用前SP=1000H，返回地址为2004H，则调用后SP=0FFCH、M[0FFCH]=2004H。

若被调过程又保存旧帧指针 FP、再分配8 B局部区，SP依次变0FF8H和0FF0H。此时局部变量不能覆盖0FFCH的返回地址。退出时先撤销局部区，恢复旧FP，再取返回地址；SP最终回到1000H。图中的地址单位为字节。

![调用、建立栈帧和返回时，SP逐步移动](CO_F06_stack_frame.png){#co-fig-stack width=96%}

嵌套调用靠每次独立保存的返回位置区分“回到哪里”；递归的各层也各有参数、局部变量和返回地址。局部变量同名不表示它们共用同一槽。调用者保存寄存器需在调用前保留自己还要使用的值；被调用者保存寄存器则在被调过程修改前保存、返回前恢复。

机器题给出具体调用约定时，按它追踪，而不是凭熟悉的 x86、MIPS 或 RISC-V 经验补条件。特别要检查栈生长方向、SP指向、入栈前后调整顺序和返回地址基准。它们会同时影响地址计算与最终返回位置。

### 自测 {#co-self4}

1. 【2025】某32位计算机按字节编址，采用小端方式存放数据，编译器按边界对齐方式为下列 C 语言结构型数组 employee 分配空间：`struct record { int id; char name[10]; int salary; } employee[200];`。若 employee 首地址为0000 A0B0H，employee[1].id的机器数为1234 5678H，则其中56H所在单元地址是（　）。A. 0000 A0C3H　B. 0000 A0C4H　C. 0000 A0C5H　D. 0000 A0C6H。
2. 原创补充：沿用本章栈模型，初始SP=1000H，连续push两个4 B值后，再pop一个值，SP是多少？返回地址保存在链接寄存器时，是否每次调用都必然产生一次主存写？

**答案。** 1. C。id占0至3，name占4至13，填充14、15，salary占16至19，结构大小20 B。employee[1].id始于A0C4H，小端的56H在其后1 B，即A0C5H。2. SP=0FFCH。否，是否写主存还取决于调用模型及是否需要溢出保存。
