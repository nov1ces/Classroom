# 审阅编辑任务模板（内部）

润色稿完成后，由审阅编辑按本科目逐章核对。审阅者**只报告，不改文件**。

## 输入

- `editorial/polish/润色规范.md`
- `editorial/polish/示范修改.md`
- 基线：`editorial/polish/baseline/<科目>/*.md`
- 现稿：`manuscript/<科目>/*.md`
- 作者报告：`editorial/polish/reports/<科目>_<章号>.md`

## 核对方法

1. 先读规范与示范，明确本轮允许改什么。
2. 对每章运行：

```bash
git diff --no-index --no-color -U2 -- editorial/polish/baseline/DS/01_xxx.md manuscript/DS/01_xxx.md
```

3. 只读改动处及其上下文，不必重读全章；对可疑处再打开现稿核对。

## 检查项（按优先级）

1. **语义漂移**：改后是否多出或漏掉一个条件；"可能/通常/部分"是否被改成"必然/一定/全部"；因果、先后、范围是否被改变；题目条件、选项、答案、数值是否被改动。
2. **知识丢失**：删掉的句子是否含定义、边界、反例、易错提醒、推导步骤；合并句子时是否压掉了关键限定。
3. **越界增写**：是否新增原文没有的断言、例子、考点提示、评价性总结。
4. **过度改写**：整段重写是否改变了叙述重点，或把具体解释压成口号。
5. **残留语病**：改后仍指代不明、搭配不当、句子读不通。
6. **一致性**：术语、数字、单位、标点、标题风格是否与同章/同科一致。

## 输出格式

每章最多 6 条，按严重度排序；只写需要动手的，不写泛泛评价。

```markdown
### DS 01 数据结构、算法与复杂度
- 结论：通过 / 小修 / 返工
- [高] 第2节"算法怎样保证结束……"：改后把"通常要求"改成"要求"，把有例外的表述绝对化。建议恢复"通常"。
- [中] 第3节例1-2：删去"按题目给定的整数模型"一句，学生可能忽略模型前提。建议保留。
- [低] 第4节："……"与前句主语重复，可删"它"。
```

## 最终回复

用一段话给出：本科目各章结论（通过/小修/返工）、高严重度问题数量、最需要主编处理的两三处。不要粘贴大段正文。
