# 408 讲义中文润色规范（第四轮）

本文件是本轮唯一的口径来源。开始改动前通读一遍；与个人语感冲突时，以本文件为准。

## 一、任务性质

这是**专业编辑**，不是重写、扩写或摘要。目标是让已经有知识密度的正文更好读：

- 句子更自然，少一些翻译腔和压缩腔；
- 概念、条件、推理、结论之间的关系更清楚；
- 该强调的地方有着落，该收住的地方不啰嗦；
- 知识点、限定条件、推导、数值、题目与答案一个不少、一个不改。

原文已经清楚顺畅的句子**不要动**。改动要有理由：读者会在哪里卡住、误解、或读得别扭，就改哪里；没有具体理由的同义替换一律不做。

## 二、读者与语体

读者是有计算机基础、正在准备 408 考研的学生。他们需要的是**讲清楚**，不是**显得高级**。

- 用规范、平实的科技书面语，不用口语、网络语、文学化比喻。
- 不堆四字格，不追求整齐排比，不写口号式判断。
- 句子长短由内容决定。该长则长，该断则断，不把整章改成短句。
- 一段话只承担一个中心意思；中心转移就分段。
- 保持原有信息密度：不增添原文没有的背景、例子、考点提示、复习建议。

## 三、优先处理的六类问题

### 1. 指代悬空、主语跳换

代词（它、此、该、这）指什么必须能从上一句直接看出；连续两个"它"指不同对象时，改回名词。

- 原：`p=NULL` 表示它目前不指向有效结点。
- 改：`p=NULL` 表示 `p` 当前不指向任何有效结点。

### 2. 否定句过密、句式单一

全稿"不能"出现约七百次，很多段落连续三四句都是"不能……"。否定提醒有价值，但要节流：

- 同一段内"不能/不应/不可"一般不超过两次；余下的改为正面陈述，或换用"并不""未必""不等于""难以""须避免"。
- 只有表示**客观不可能**或**明确禁止**时才用"不能"；表示"这样理解不对"时，优先写清楚正确的理解。
- 不削弱原有的技术禁令：改的是句式，不是语气强度。

- 原：`sum` 最终约为 $n$，不能推出执行了 $n$ 轮；每轮增加量也在增长。
- 改：`sum` 最终约为 $n$，不能据此推出执行了 $n$ 轮——每轮的增量本身也在增长。

### 3. 名词化与空动词

"进行……的检查""对……作出判断""关于……的问题""实现……的功能"这类结构，改成直接动词。

- 原：对临界区方案进行正确性检查时……
- 改：检查临界区方案是否正确时……

但术语本身含"实现""处理""管理"的（如"实现互斥""缺页处理"）不要硬改。

### 4. 长定语与"的"字链

一个名词前挂三个以上修饰成分，或出现"……的……的……"，拆成两小句，或把其中一层改成谓语。

- 原：一个记录了所有尚未完成且已经超时的请求的队列
- 改：这个队列记录所有尚未完成、已经超时的请求。

### 5. 逻辑连接缺失或错位

原文常把因果、转折、条件压成并列短句，读起来像结论罗列。补足必要的连接词（因此、但、若、也就是说），**只在确有逻辑作用时补**；不要每段都加"因此"。

- 原：B 只表达了先后约束。
- 改：选项 B 只概括了先后关系，没有涵盖互斥。

条件句先条件后结论；"若……则……"不要省掉"则"造成两可。

### 6. 重复与冗余

同一段里重复出现的定义、同义反复、没有信息量的收尾句，删掉或合并。**不删知识点**，只删重复表述。

- 原：这里的输出可以是返回值，也可以是修改后的数据状态，不能只把屏幕打印当作输出。
- 改：输出不限于屏幕打印，也可以是返回值或修改后的数据状态。

## 四、不得改动的内容

以下任一情况都算越界，检查脚本会报错：

1. 标题层级、`{#...}` 锚点、图片路径与图注锚点；
2. 代码块内容（含伪代码、C 代码、汇编表）、缩进与空行；
3. 数学公式（`$...$` 与 `$$...$$`）的内容；包括增删一个符号、改变下标；
4. 表格的行列数、表头与单元格的对应关系；
5. 题源标记（【年份】、〖节号-题号〗）、题干条件、选项、答案字母；
6. 数值、单位、进制、地址、位宽、时序数字；
7. 术语名称（Cache、TLB、PCB、CSMA/CD 等），以及"通常/一般/可能/在……条件下"等限定词；
8. "原创""改编"等标注。

发现疑似事实错误（定义、数值、结论、题解）时：**保留原文，不改**，写入报告的"疑似问题"一节，注明位置与理由。错别字、明显的标点误用可以直接改，但要在报告中列出。

## 五、例题解析的改法

解析的结构通常是：定位题眼 → 推理/计算 → 结论 → 易错点。可以调整这个顺序、补连接词、把长句拆开，但：

- 计算过程、中间值、最终选项不变；
- 不能把"为什么这样算"删掉换成结论；
- 易错提醒、边界条件、反例要保留；
- 不新增第二种解法、不扩展题目背景。

## 六、标题

标题可以改得更具体、更短、更像问题，但：

- 层级不变，锚点不变；
- 例题标题保持 `### 例 X-Y　标题` 的格式，编号与全角空格不动；
- 不把陈述式标题统一改成疑问式，也不为了整齐把所有标题改成同一长度。

## 七、格式与排印

- 中文标点用全角；并列词语之间用顿号，分句之间用分号，不用逗号一逗到底。
- 中文与拉丁字母、数字之间，原文已有空格的地方保持空格；原文没有的，不逐处补，避免制造大量无意义差异。仅当同一句内明显不一致时（如"改善Cache通常"），补齐该处。
- 数字范围用"～"或"至"，与原文一致；不混用"-"。
- 不手工断行，段落保持一行一段。

## 八、改动尺度

- 改动量由实际问题决定，不设指标。原文准确顺畅处保留；问题密集的章节改到三成也正常，基础较好的章节改一成也正常。
- 全章汉字数变化控制在 **±3%** 以内。润色的常态是略减或持平，不是变长。
- 一段话改完后，出声读一遍：如果一口气读不完，或需要回头找主语，就再改。

## 九、工作步骤

1. 读 `editorial/polish/baseline/<科目>/<章>.md`（改前基线）和 `manuscript/<科目>/<章>.md`（现稿，两者当前相同）。
2. 通读全章，列出 3～5 处真正影响理解的问题，再动笔。
3. 用 `edit` 工具做定点修改；不要整篇重写，不要用脚本批量替换句子。
4. 每改完一节，回读该节；整章改完后通读一遍。
5. 运行自检：

```bash
python editorial/polish/tools/check_manuscript.py --subject <DS|CO|OS|CN>
```

只应出现 `[ok]`；`soft` 中的汉字数变化应在 ±3%。若报 `HARD`，说明动了不该动的东西，必须改回。

6. 写报告 `editorial/polish/reports/<科目>_<章号>.md`，格式见下。

## 十、报告格式

```markdown
# <科目> <章名> 润色记录

## 改动概况
- 改动句数：约 N 句（占全章约 X%）
- 汉字数：A → B（±X%）
- 自检：check_manuscript 通过

## 主要改动类型
- （如）补足条件句的"则"，拆开三处长定语
- （如）把连续四句"不能"改为正面陈述两句
- （如）统一"结点"用法，修正两处"节点"

## 代表性修改
1. 原：…… / 改：……（理由一句话）
2. ……

## 疑似问题（未改）
- 位置：第 N 节"……"；现象：……；建议：请核对。
```

没有疑似问题就写"无"。

## 十一、明确不要做的事

- 不要为了"更像教材"而加"本节介绍……""下面我们来看……""综上所述"。
- 不要把陈述改成设问，再把设问自答一遍。
- 不要把所有"因为"改成"由于"、所有"但是"改成"然而"这类同义替换。
- 不要在每段末尾加总结句。
- 不要把并列的三项改成排比句。
- 不要删除原文的易错提醒、反例、限定条件来换取流畅。
- 不要因为"读起来不顺"就改动公式、代码、题干的顺序。
