## 来源差异与限定处理

| 位置 | 差异或容易过度推导的表述 | 本轮处理 |
| --- | --- | --- |
| IPv4课件p14；主书p150 | 课件称IPv4首部检验和全0可表示不用校验 | 不沿用。正文明确IPv4没有此关闭约定；复算构造检验和恰为0且仍须校验的合法首部，改TTL后应失败 |
| IPv4课件p6～7、以太网课件p8；主书p104 | “IP过短就填充”可能被误解为改写IP总长度 | 填充归MAC数据区，40 B IP仍为40 B；无标签MAC帧增加6 B填充到64 B；MTU仍限制完整IP分组 |
| UDP课件p5；主书p241～242、150 | UDP长度字段最大65535 B可能被误作普通IPv4应用载荷上界；零字段说明没有列IP版本 | 分开字段编码上界与IPv4总长上界，20 B IP首部时应用载荷最多65507 B；保留IPv4可选与IPv6通常强制的区别 |
| TCP课件p9；主书p249～250 | 经典图保留6 bit，现代TCP扩展可能另用部分原保留位 | 图严格采用主书经典6+6模型；扩展须按题图/条件解释，不无条件拼入现代位图 |
| TCP课件p10；主书p249～250 | PSH简写成“尽快回复”，紧急指针简写成“专用序号” | PSH解释为及时向应用交付；紧急指针是相对边界、16 bit，不能当独立32 bit序号；不误加序号消耗 |
| TCP课件p8、11 | “只有握手① ACK=0”等句依赖常规握手/释放示例 | 正文采用ACK=1才使确认号有效等字段语义，不推广成包括RST等情形的无条件断言 |
| SR课件p3～6；主书p78 | 新旧序号不重叠约束与教材常用Wr≤Ws不是同一理由 | 同时写出两者；对称半空间结论带等窗条件，4位Ws9/Wr7仍合法；代码分别检查不重叠与教材配置 |
| 主书p203与p205 | 前文“仅变化时更新”易被读成无任何周期动作 | 对照后文数据库刷新、老化与邻居维护，表中写变化触发且仍需刷新/老化，不把Hello当拓扑变化通告 |
| 主书p304；HTTP课件p6 | 流水阶段若干小对象1RTT不等于整页始终1RTT | 先HTML，再后续请求；统一初态表单列握手，保留发送、拥塞、流控、跨服务器等适用条件 |
| 主书p239、306的基础应用表 | DNS列UDP、FTP数据列20是基础模型汇总 | 不由简表推出排他结论；保留既有正文DNS可TCP及FTP主动/被动的数据端口条件，本轮应用对照同步这些限定 |
