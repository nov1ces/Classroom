## OS-EX-2024-46　单缓冲区：同步条件和互斥条件分别在问什么


题源：[2024重建卷](https://raw.githubusercontent.com/neville-studio/408-exam-paper/main/papers-rebuild/2024.pdf)第11页，第46题；王道2.3综合题28。


### 完整题干


（8分）计算机系统中的进程之间往往需要相互协作以完成一个任务。在某网络系统中，缓冲区B用于存放一个数据分组，对B的操作有C1、C2和C3。C1将一个数据分组写入B中，C2从B中读出一个数据分组，C3对B中的数据分组进行修改。要求B为空时才能执行C1，B非空时才能执行C2和C3。
（1）假设进程P1和P2均需要执行C1，实现C1的代码是否为临界区？为什么？（2分）
（2）假设B初始为空，进程P1执行C1一次，进程P2执行C2一次。请定义尽可能少的信号量，并用wait()、signal()操作描述进程P1和P2之间的同步或互斥关系，说明所用信号量的作用及其初值。（3分）
（3）假设B初始不为空，进程P1和P2各执行C3一次。请定义尽可能少的信号量，并用wait()、signal()操作描述进程P1和P2之间的同步或互斥关系，说明所用信号量的作用及其初值。（3分）


### 识别条件与独立求解


（1）是。C1修改共享的缓冲区B及其空/非空状态，两个进程并发执行会争用同一空缓冲区，因此实现该共享资源访问的代码属于临界区。
（2）设done=0，表示P1完成唯一一次写入的通知。P1：C1; signal(done);。P2：wait(done); C2;。P2只有在P1完成C1后才可能执行C2；P1不再进行第二次写入，所以两次缓冲操作不会重叠，无需再加mutex。一个信号量足够；若不设置任何同步手段，P2可能先读空缓冲区。
（3）设mutex=1。P1和P2均执行wait(mutex); C3; signal(mutex);。第一个进入者把许可从1取走，另一个必须等其归还。C3只修改已有分组而不把缓冲区清空，因此无需另设非空通知。


part2：


```text
semaphore done = 0;
P1: C1; signal(done);
P2: wait(done); C2;
```


part3：


```text
semaphore mutex = 1;
P1: wait(mutex); C3; signal(mutex);
P2: wait(mutex); C3; signal(mutex);
```


### 选题和边界


模型：一次写后一次读的先后约束；两个修改者的互斥约束

入选理由：同一道真题把临界区、先后约束、最少信号量放在可区分的三个情境中，适合作为概念后的第一道代表题。

相对新增：区别于多次生产消费：第（2）问仅各执行一次，单个同步信号量足以保证互斥。

删除检查：删除后会失去“同一缓冲区随操作和执行次数改变信号量模型”的边界辨析。


- 第（2）问“各一次”是只用一个信号量的必要限定；改成反复写读需要空位许可。
- 第（3）问假定只有题干所列的两个C3操作，不引入额外C2取走分组。


原答案对照：与王道第28题答案一致；教材关于“容量为1即可省互斥量”的说明在本题还依赖仅一次写和一次读，不能脱离这一限定推广。

## OS-EX-2022-46　前趋图：只对跨线程的约束设置信号量


题源：[2022重建卷](https://raw.githubusercontent.com/neville-studio/408-exam-paper/main/papers-rebuild/2022.pdf)第10页，第46题；王道2.3综合题26。


### 完整题干


（8分）某进程的两个线程T1和T2并发执行A、B、C、D、E和F共6个操作，其中T1执行A、E和F，T2执行B、C和D。题46图表示上述6个操作的执行顺序所必须满足的约束：C在A和B完成后执行，D和E在C完成后执行，F在E完成后执行。请使用信号量的wait()、signal()操作描述T1和T2之间的同步关系，并说明所用信号量的作用及其初值。


### 识别条件与独立求解


设S_AC=0表示A已经完成，S_CE=0表示C已经完成。T1依次执行A; signal(S_AC); wait(S_CE); E; F;。T2依次执行B; wait(S_AC); C; signal(S_CE); D;。T2执行C时，B已经由本线程执行完，且wait(S_AC)已经取得A完成的通知，所以C的两个前提均满足。T1执行E时已经收到C完成的通知，再按程序顺序执行F。D在本线程的C之后；C完成后T1与T2均可继续，D与E/F的相对先后由调度决定。


T1：


```text
A;
signal(S_AC);
wait(S_CE);
E;
F;
```


T2：


```text
B;
wait(S_AC);
C;
signal(S_CE);
D;
```


initial：


```text
semaphore S_AC=0, S_CE=0;
```

## OS-EX-2009-45　分类缓冲：有产品不等于有本进程可取的产品


题源：[2009重建卷](https://raw.githubusercontent.com/neville-studio/408-exam-paper/main/papers-rebuild/2009.pdf)第8页，第45题；王道2.3综合题17。


### 完整题干


（7分）三个进程P1、P2、P3互斥使用一个包含N（N>0）个单元的缓冲区。P1每次用produce()生成一个正整数并用put()送入缓冲区某一空单元中；P2每次用getodd()从该缓冲区中取出一个奇数并用countodd()统计奇数个数；P3每次用geteven()从该缓冲区中取出一个偶数并用counteven()统计偶数个数。请用信号量机制实现这三个进程的同步与互斥活动，并说明所定义信号量的含义（要求用伪代码描述）。


### 识别条件与独立求解


原题未声明缓冲区初态；按王道参考答案采用初始为空，故empty=N、odd=even=0。mutex=1保证put、getodd和geteven互斥。生产者在本地生成x，先wait(empty)预留空位，再wait(mutex)进入缓冲区，put()后释放mutex；若x为奇数则signal(odd)，否则signal(even)。消费者只有收到所属类别的许可后才进入缓冲区取数，随后释放mutex并signal(empty)，统计放在锁外。这样没有消费者会取不存在的类别，缓冲区也不会写满后继续写。某类别长期没有产生时，其消费者可以一直等待，这由输入决定，并非算法的死锁。


initial：


```text
semaphore empty=N, odd=0, even=0, mutex=1; //按初始为空
```


P1：


```text
while (true) {
  x=produce();
  wait(empty);
  wait(mutex);
  put(); //放入本次生成的x，保留题设函数名
  signal(mutex);
  if (x%2==1) signal(odd); else signal(even);
}
```


P2：


```text
while (true) {
  wait(odd);
  wait(mutex);
  getodd();
  signal(mutex);
  signal(empty);
  countodd();
}
```


P3：


```text
while (true) {
  wait(even);
  wait(mutex);
  geteven();
  signal(mutex);
  signal(empty);
  counteven();
}
```


### 选题和边界


模型：有限缓冲区的容量许可 + 按类别分配的产品许可 + 共享缓冲区互斥

入选理由：在标准生产消费上增加“消费者只能取特定类别”，逼迫学生从实际等待条件决定计数信号量。

相对新增：空位计数共用，产品计数按奇偶拆开；自然检验wait顺序与临界区长度。

删除检查：删除后会失去“一个full无法表示两类不同可取条件”的真题边界。


- 原题未另写“初始为空”，但王道答案使用odd=even=0、empty=N；重排正文须把“以下按初始为空求解”作为解答的显式假设，不能静默插入原题。若初始有a个奇数、b个偶数，则empty=N-a-b、odd=a、even=b，且a+b≤N。
- 不能用单一full代替odd/even：即使缓冲区非空，也可能没有P2或P3需要的类别。
- 不能先wait(mutex)再wait(odd/even/empty)：否则可能占锁等待，使解除该等待的进程无法访问缓冲区。
- empty/odd/even在有进程已经取得许可但尚未完成操作时表示未被预留的许可数，不能每一步都等同于物理空位或实存元素数。


原答案对照：信号量及操作顺序与王道第17题一致；补明原题未明确写出的初始为空假设；原书只有本页即完整收录答案，旧提取器误将p155顶端空白并入，答案定位修正为物理p154/印142。


个人错题信息：本台账没有将本题认定为个人错题；原作答和个人错因均未从题源中获得，不作推测。


## OS-EX-2014-47　连续取十件：单次缓冲操作和整批消费者分别互斥


题源：[2014重建卷](https://raw.githubusercontent.com/neville-studio/408-exam-paper/main/papers-rebuild/2014.pdf)第11页，第47题；王道2.3综合题20。


### 完整题干


（8分）系统中有多个生产者进程和多个消费者进程，共享一个能存放1000件产品的环形缓冲区（初始为空）。当缓冲区未满时，生产者进程可以放入其生产的一件产品，否则等待；当缓冲区未空时，消费者进程可以从缓冲区取走一件产品，否则等待。要求一个消费者进程从缓冲区连续取出10件产品后，其他消费者进程才可以取产品。请使用信号量P、V（或wait()、signal()）操作实现进程间的互斥与同步，要求写出完整的过程，并说明所用信号量的含义和初值。


### 识别条件与独立求解


设empty=1000表示未预留的空槽许可，full=0表示未预留的产品许可；mutex=1保证单次放入、取出及指针修改互斥；batch=1保证同一批十次取数由一个消费者独占。消费者先wait(batch)，再循环十次：wait(full)、wait(mutex)、取buf[out]并更新out、signal(mutex)、signal(empty)。十次完成后signal(batch)，再处理本地的十件产品。生产者每次wait(empty)、wait(mutex)、写buf[in]并更新in、signal(mutex)、signal(full)。消费者缺货时只持有batch而没有mutex，生产者不需要batch，因而仍能补货；其他消费者则被batch挡住。


initial：


```text
semaphore empty=1000, full=0, mutex=1, batch=1;
int in=0, out=0;
item buf[1000];
```


producer：


```text
while (true) {
  x=produce();
  wait(empty);
  wait(mutex);
  buf[in]=x; in=(in+1)%1000;
  signal(mutex);
  signal(full);
}
```


consumer：


```text
item local[10]; //每个消费者的私有数组
while (true) {
  wait(batch);
  for (int k=0; k<10; ++k) {
    wait(full);
    wait(mutex);
    local[k]=buf[out]; out=(out+1)%1000;
    signal(mutex);
    signal(empty);
  }
  signal(batch);
  consume(local);
}
```


### 选题和边界


模型：有限环形缓冲区 + 消费者批次互斥，允许生产者在消费者批内继续生产

入选理由：“连续取10件”会改变互斥粒度，不能仅把标准消费者代码循环十次；同时能揭示持有共享缓冲锁等产品的死锁。

相对新增：标准有限缓冲区不能覆盖消费者之间的整批排他；题目条件直接决定额外batch信号量。

删除检查：删除后会失去批次约束改变锁范围，以及“批内等待仍须允许生产”这一边界。


- 连续是指其他消费者不得插入取走产品；不要求生产者在这十次之间停止放入。
- 不要求开始时已有10件；允许消费者取若干件后等待生产者继续补货。
- 只有一个普通mutex贯穿整批会在产品不足时阻止生产者补货。
- 若在batch外由多个消费者分别先wait(full)十次，可能各预留不足10件，造成许可分散；先锁batch再逐件申请。


原答案对照：原书p156说明段将mutex1解释为整批、mutex2解释为单次，但代码注释和实际操作则是mutex1生产者互斥、mutex2消费者整批互斥，命名不一致。原书代码在环形缓冲区生产者/消费者使用独立in/out、由empty/full保证不同槽位的前提下可行；本讲义采用更易核查的共享mutex+batch四信号量解法，数值、题意、设问均未改动，属于同题另一正确解法。

## OS-EX-2025-45　植树协作：容量配额、工具互斥与阶段完成通知


题源：[2025重建卷](https://raw.githubusercontent.com/neville-studio/408-exam-paper/main/papers-rebuild/2025.pdf)第10页，第45题；王道2.3综合题29。


### 完整题干


（7分）甲、乙、丙三人一起植树，甲负责挖树坑，乙负责将树苗放入树坑中并填土，丙负责为新种的树苗浇水。植树的步骤依次为：挖树坑、放树苗、填土和浇水。现有铁锹和水桶各1个，铁锹用于挖树坑和填土，水桶用于浇水。当树坑的数量小于3时，甲才可以挖树坑。假设初始时树坑的数量为0，铁锹和水桶均可用。请定义尽可能少的信号量，用wait()、signal()操作描述植树过程中三人之间的同步或互斥关系，并说明所用信号量的作用及其初值。


### 识别条件与独立求解


使用四个信号量：position=3、pit=0、tree=0、shovel=1。甲wait(position)，wait(shovel)，挖坑，signal(shovel)，signal(pit)。乙wait(pit)，放苗，signal(position)，wait(shovel)，填土，signal(shovel)，signal(tree)。丙wait(tree)，浇水。各自重复以上过程。甲获得一个配额才挖坑；乙放苗后空坑已被使用，及时归还配额；乙填土完成后才通知丙浇水。甲乙的铁锹区互斥，水桶只有丙使用。


initial：


```text
semaphore position=3, pit=0, tree=0, shovel=1;
```


甲：


```text
while (true) {
  wait(position);
  wait(shovel);
  挖树坑;
  signal(shovel);
  signal(pit);
}
```


乙：


```text
while (true) {
  wait(pit);
  放树苗;
  signal(position);
  wait(shovel);
  填土;
  signal(shovel);
  signal(tree);
}
```


丙：


```text
while (true) {
  wait(tree);
  浇水;
}
```


### 选题和边界


模型：三阶段流水线中的中间产物计数、未用树坑容量和共享铁锹互斥

入选理由：可检验学生是否只为真正共享的水桶/铁锹建模，是否正确确定空坑配额的归还时刻。

相对新增：甲乙共享铁锹但丙独占水桶，无需水桶互斥量；放入树苗后即归还空坑配额。

删除检查：如不收录，本单元已有四题仍能完成主要教学任务；本题新增三阶段共享资源建模，可后续综合章保留。


- “树坑数量”按王道参考答案解释为尚未放树苗的空坑数，放入树苗即释放其空坑配额。
- 若把position一直等到浇水后才释放，会施加“未浇水树苗与空坑总数至多3”的额外限制，减少原题允许的并发。
- 只有甲乙争用铁锹；“资源只有一个”不能单独推出需要互斥量，还要看是否有多个使用者。


原答案对照：四信号量与王道第29题答案一致，mutex改名shovel仅为清楚表意，不改题干或解法。
