# 同步与信号量候选题独立复算说明

实际执行 `python verify_os_examples.py`，结果写入同目录 `verification_results.json`。核验时间为2026-10-15。脚本只使用Python标准库，有限状态检查不是一般性证明的替代品。

## 2022年第46题：保持且仅保持给定的先后约束

题图五条边为A→C、B→C、C→D、C→E、E→F。按两线程代码顺序执行，B→C、C→D、E→F已经成立，剩下两条跨线程边由两个初值0信号量实现。任一次C执行前必已经过A后的signal和B本身；任一次E执行前必经过C后的signal，所以全部图约束成立。

脚本把信号量操作本身作为原子动作，穷举了34个状态、36次转移，得到全部6种可见操作次序：ABCDEF、ABCEDF、ABCEFD、BACDEF、BACEDF、BACEFD。再独立枚举6顶点所有排列，筛出满足五条边的拓扑序，二者集合完全相等。因此实现没有额外要求D先于E或F。

## 2024年第46题：操作次数决定能否省略信号量

第（2）问使用一次完成通知，写入操作被细分为进入/完成，读出也被细分为进入/完成。7个状态的完整枚举中，读出只可能在写入完成并通知后发生，两个操作没有重叠。这里不需要第二次写的空位许可，因为P1只写一次。

第（3）问用“两个进程分别把同一个值加1”的小实例检查读改写互斥，起始值0。加锁版本所有执行的终值都是2；去掉锁后终值可能是1或2，出现更新丢失。这个加一实例仅为解释临界区所需互斥，不是对原题C3的改写或额外条件。

## 2009年第45题：许可、物理元素与预留量

原题没有说明初始缓冲区内容。按王道答案的初始为空解释，empty=N、odd=even=0。如果初始有a个奇数、b个偶数，应改为empty=N−a−b、odd=a、even=b，且a、b非负、a+b≤N；不能把空初态静默补进原题题干。

在不执行任何缓冲访问的中间静止点，empty等于物理空槽数、odd/even等于相应元素数。在细化到每个P/V动作的执行状态中，这种简单等式会暂时失效，因为许可可能已经被某个进程取得，或数据已写入但尚未发布许可。脚本检查的是包含预留量的精确等式：

- empty许可 + 物理元素数 + 生产者已取empty但尚未放入的数量 + 消费者已取走但尚未归还empty的数量 = N。
- 每类物理元素数 = 该类未分配许可 + 生产者已放入但尚未发布该类许可的数量 + 该类消费者已取许可但尚未取数的数量。
- mutex许可 + 正在缓冲临界区的进程数 = 1。

所以每个get确有对应类别，每个put确有槽位，三个缓冲操作不会重叠。等待产品或空位时均不占mutex；若生产者等空位，已有元素可由对应消费者取出；若全部消费者等产品，生产者可以继续放入（只要被调度）。按容量1、2、3分别穷举116、444、1060个可达状态，全部满足这些等式且无全局死锁。输入长期不产生某类数时，相应消费者等待是条件不成立，并非算法凭空制造的死锁；公平性仍是进展讨论的外部假设。

## 2014年第47题：整批互斥与缓冲互斥的范围不同

共享mutex只包围一次put/get及其in/out修改，batch只由消费者持有，覆盖连续十次取数。batch=1使任意时刻只有一个消费者在批内；mutex=1使各次缓冲修改互斥。每次取数先取得full，再取得mutex，因此缺货时不会占住生产者需要的mutex。生产者从不申请batch，所以仍能在批内补货。

把每次P、V、put/get、循环条件都作为独立状态转移，使用两个生产者、两个消费者、每批十件。小容量1、2、3分别枚举510、1973、4076个状态，检查容量守恒、许可预留量、临界区唯一性、批内消费者唯一性，未见全局死锁。容量1仍能正确完成十次取数，验证了“开始一批不要求已攒够十件”的边界。

原容量1000另用固定随机种子408执行100000步交错，实际放入9482件、取走8482件，最终1000件，全部检查通过。这是容量1000的一条长执行，不是1000槽全部状态的穷举，也不是统计频率结论。一般正确性依赖前述守恒式和锁范围说明。

王道p156/印144的说明段与代码对mutex1/mutex2的命名不一致。本候选解采用共享mutex加batch，未修改题干、数值或问题；它是同题另一个正确实现。原书的生产者互斥量与消费者批次互斥量分开实现，在独立in/out环形队列及正确容量许可的前提下也可成立。

## 2025年第45题：释放空坑配额的时刻

按王道解释，“树坑数量”指尚未放入树苗的空坑。甲先取得position配额再拿铁锹；乙放入树苗后即归还position，再拿铁锹填土；填土完成才发布tree。水桶只有丙使用，无第二使用者与其竞争，不加水桶互斥量。

脚本同时跟踪实际空坑数、待浇水数、未发布的坑或树苗、已被下游预留的许可，检查position与预留量的总和恒为3、空坑从不超过3、铁锹只有一个持有者、各阶段不提前。每人1、3、4轮分别枚举15、270、620个状态，均能完成，无全局死锁。

上述结果不证明任意不公平调度下都无饥饿；原题亦未指定信号量等待队列公平性。成稿若介绍饥饿，须与死锁区分。
